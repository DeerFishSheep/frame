一、项目定位

项目暂定名称：FRAME 帧榜

我要做的是一个专门用于浏览每日影视排行榜、探索优秀电影和电视剧的网站。

网站应当具有以下特点：

* 每天都能看到最新的影视热度与排行榜。
* 汇集电影、电视剧的趋势、高分、热门、上映等榜单。
* 支持不同维度的电影发现与精准筛选。
* 提供优秀的中文影视资料浏览体验。
* UI 简约、高级、优雅，视觉设计达到精品产品水准。
* 桌面和手机端都具备完整且流畅的交互体验。

这不是在线播放或影视资源站，而是一个影视信息、榜单与内容发现平台。

二、之前讨论过的关键结论

1. TMDB 与 IMDb 的定位

TMDB 是首期核心数据来源。

它有适合开发者调用的 API，可以获取：

* 每日与每周影视趋势；
* 热门和高分电影、电视剧；
* 正在上映及即将上映作品；
* 电影海报、背景图、评分、投票数；
* 中文电影名称、剧情介绍；
* 影片类型、关键词、演员、导演；
* 相似作品、推荐作品等信息。

IMDb 的大众评分、Top 250 等排行榜有参考价值，但其官方实时数据通常需要相应的授权。

第一版优先完整接入 TMDB，不依赖未经许可的 IMDb 数据抓取。

后续保留其他平台的数据适配层。不得把 TMDB 分数冒充 IMDb 分数。

2. 类型和关键词的局限

我们之前研究过 TMDB 的电影类型、关键词和 Discover 接口。

发现一个问题：

单纯按照电影类型或关键词筛选，无法准确反映用户真正的观影偏好。

比如喜欢悬疑、烧脑电影，不代表喜欢所有恐怖电影。

因此网站除常规类型筛选以外，还应考虑后续增加人工精选片单、复合筛选和个性化找片功能。

例如：

* 高能反转
* 悬疑烧脑
* 时间循环
* 心理悬疑
* 犯罪推理
* 高概念科幻

这些属于策展专题，不应虚构为 TMDB 官方电影类型。

三、第一阶段必须实现的功能

1. 影视排行榜

支持以下主要榜单：

榜单	数据来源
今日电影趋势	/trending/movie/day
本周电影趋势	/trending/movie/week
今日剧集趋势	/trending/tv/day
本周剧集趋势	/trending/tv/week
热门电影	/movie/popular
高分电影	/movie/top_rated
正在上映	/movie/now_playing
即将上映	/movie/upcoming
热门电视剧	/tv/popular
高分电视剧	/tv/top_rated
今日播出剧集	/tv/airing_today
近期在播剧集	/tv/on_the_air

首页默认展示今日趋势。

需要支持榜单切换、电影与剧集切换、分页和加载更多。

可以增加综合趋势，但需要正确处理 TMDB /trending/all 可能返回人物的情况。

榜单序号必须与真实排序一致。

2. 搜索和高级筛选

需要支持：

* 电影和电视剧搜索
* 多选电影类型
* 年份范围
* 评分区间
* 评分人数下限
* 制片地区或原始语言
* 类型或关键词组合
* 不同排序方式

使用 /discover/movie、/discover/tv 实现真正的 API 筛选。

尤其注意：不要只对当前页面获取的 20 部电影进行本地筛选，却把结果当作全站筛选。

多选类型要支持逻辑组合，遵循 TMDB 的 AND/OR 参数规则。

筛选状态应尽量可以通过 URL 保存和分享。

3. 影视详情

每部作品都必须可以进入详情页面。

电影资料包括：

* 中文片名及原名
* 海报、剧照、背景图
* 剧情简介
* 上映年份、日期和地区
* 类型与关键词
* TMDB 评分与投票人数
* 导演、演员、片长
* 相似及推荐作品
* 官方 TMDB 页面链接
* 如果存在 IMDb ID，则提供 IMDb 页面链接

剧集需要显示对应的首播时间、季数、播出状态和演员等信息。

可以利用 TMDB append_to_response 一次获取多个关联资源，但必须处理缺失数据。

4. 收藏片单

用户不登录也可以使用收藏功能。

要求：

* 收藏和取消收藏
* 独立的收藏页面
* 支持电影与剧集
* 刷新页面不丢失数据
* 后续能够扩展账户同步

第一版使用浏览器 localStorage 即可。

5. 榜单更新

通过服务端定期获取 TMDB 数据并缓存。

建议初期缓存时间约为 30 分钟，视数据性质调整。

页面必须显示数据来源和最近更新时间。

TMDB 日榜不等于逐秒更新的实时播放数据。

尚未保存历史榜单时，不允许凭空生成名次变化、热度增长或新上榜标识。

四、UI/UX 设计要求

我很重视前端的完成度。

请重点参考提供的 frame_ranking_demo.html 和设计截图。

整体风格

关键词：

Premium Minimal / Cinematic / Editorial / Elegant

视觉上希望像高端电影杂志或精品影视发现产品。

不要采用传统影视门户的密集卡片和复杂导航风格。

基本方向：

* 以深蓝黑色系为默认背景。
* 使用低饱和香槟金作为强调色。
* 排版精致、层次清晰、留白舒适。
* 大标题可使用优雅的衬线字体。
* 正文采用现代易读的中文字体。
* 卡片、按钮、筛选器风格统一。
* 动画克制、自然、顺畅。
* 同时支持精致的浅色主题。

可以参考原型的色彩：

* 背景：#0c1015
* 文字：#f4f0e8
* 强调色：#e0c6a1

页面布局

桌面端：

* 左侧精致侧边导航
* 顶部导航和操作区域
* 首页 Hero 展示区
* 榜单标题和介绍
* 电影/剧集切换
* 日榜/周榜切换
* 筛选与搜索工具栏
* 海报网格及列表视图

移动端：

* 适合小屏的独立响应式布局
* 收纳式导航
* 易于点击的筛选控件
* 合理的海报排列和字体尺寸
* 无横向溢出和布局错乱

交互细节

确保所有可见控件真正有功能，包括：

* 页面切换
* 筛选切换
* 搜索输入
* 排序变化
* 收藏操作
* 详情弹窗或详情页面
* 主题切换
* 加载更多
* 移动端菜单

需要完整设计骨架屏、错误反馈、空结果及重新加载等状态。

UI 漂亮与实际功能都必须做到，不接受只有视觉效果的空壳。

五、技术架构建议

默认建议：

* Next.js App Router
* TypeScript
* Tailwind CSS
* 适度使用 shadcn/ui 或 Radix UI
* 服务端 TMDB API 客户端
* 合理的数据缓存及错误处理
* 类型安全、可复用组件
* 为后续数据库及多来源扩展预留接口

如果工作目录已有技术栈，优先判断是否能沿用。

API 安全

正式网站应将 TMDB 凭证放在服务器环境变量中，例如：

TMDB_API_READ_ACCESS_TOKEN

浏览器不直接持有服务端 API 凭证。

原型的“输入 Key 连接 TMDB”功能只用于演示，生产版本应通过后端访问 TMDB。

提供 .env.example，不能把密钥写死到源代码。

处理请求超时、HTTP 429、请求失败以及缓存回退。

数据结构

建立统一电影/剧集类型模型。

特别注意：

* 电影与剧集可能使用相同数字 ID，必须区分 mediaType。
* 榜单结果中的 genre_ids 与详情接口中的 genres 结构不同。
* TMDB 中文名称缺失时要合理回退。
* 评分必须显示正确的平台归属。
* 影片海报使用 TMDB 真实图片，并支持懒加载与占位。

六、后续阶段：让我这个站点真正有特色

第一版成功后，再开发：

1. 每日历史榜单

定时保存排行榜快照。

实现：

* 昨日与今日名次对比
* 上升、下降、持平
* 新上榜
* 近 7 天、30 天排名变化
* 历史日期榜单浏览

数据必须来自真实历史记录。

2. 专题精选片单

设计一个灵活的专题系统。

例如“悬疑烧脑精选”，允许人工维护 TMDB ID 列表，并自动关联影片信息。

3. 更精准的电影发现

结合类型、关键词、排除条件、用户偏好、收藏和相似作品，逐渐提供更高质量的推荐。

4. 多平台聚合

将来探索合法接入 IMDb、豆瓣等平台的数据。

网站架构应便于增加数据源，但不要在第一版引入不必要的开发复杂度。

七、数据与合规要求

* 清楚标识 TMDB 数据来源。
* 按照 TMDB 的要求展示相应署名和使用声明。
* 不编造电影评分、排名或历史变化。
* 区分官方榜单与本站自定义筛选结果。
* 不将演示数据混入真实排名。
* 不通过未经授权的 IMDb 抓取冒充官方数据服务。
* 如将来用于商业化，需先确认相应数据授权。

八、开发执行方式

请按照顺序工作：

1. 读取项目资料和 HTML 原型，理解功能与设计目标。
2. 初始化项目并搭建组件化、响应式的 UI。
3. 接入真实 TMDB 数据，完成全部 MVP 核心页面。
4. 实现搜索、筛选、详情、收藏和完善的交互状态。
5. 运行应用，完成桌面及移动端检查。
6. 测试API 错误、页面加载、类型映射和收藏持久化。
7. 交付启动命令、README、环境变量模板及功能完成情况。

不要一开始就实现所有未来功能。

先确保 MVP 真实可用、稳定、好看。

遇到一般技术决策时自行采用合理默认方案，不要反复询问。遇到确实需要我提供凭证或授权的地方，再明确指出阻塞项。
